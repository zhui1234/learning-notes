# school_2026_round3_E. 汉诺塔与未移动盘子编号之积

- 链接:待补充(校内赛题面)
- 难度:待补充
- 标签:`数学` `二进制` `位运算` `快速幂` `模逆元`
- 状态:待补充
- 用时:待补充
- 日期:2026-11-04
- 代码:[本地代码](../problems/school/2026_round3/E.cpp)

## 题意

- 汉诺塔问题,按最少步骤移动,移动过程中每一步移动的盘子编号形成固定序列。给出k和x,求编号为k的盘子在第x次被移动后所有没有被移动的盘子编号之积.

## 思路

### 思考路径

1. 先观察汉诺塔移动序列：`1, 2, 1, 3, 1, 2, 1, 4, …`。我想利用同一个盘子两次移动的间隔，把 `k, x` 对应到某一步，但直接计算步数可能超过 `i64`，没有继续化简。
2. 我还尝试把移动非 1 号盘的时刻对应到随后移动 1 号盘的时刻。这个方向仍然在追踪完整操作序列，没有抓住答案只依赖“已移动的最大编号”。
3. 后来通过列表找规律：令 `a[i][j]` 表示第一次移动 i 号盘之前，j 号盘最多被移动多少次，则 `a[i][j] = 2^(i-j-1)`（`i > j`）。例如 i 为 2、3、4、5 时，j=1 对应 1、2、4、8；j=2 对应 1、2、4；j=3 对应 1、2。具体数字比直接推字母更容易看出翻倍关系。
4. 我原来把最大已移动编号写成 `k + log₂x`，取整没有写清楚。应为 `k + ⌈log₂x⌉`，不能向下取整；例如 `k=1, x=3` 时已经移动过 3 号盘。
5. 实现时还卡在模除法和位移溢出：阶乘相除要乘逆元；`1 << 32` 不能先按 int 计算再转换，需要用 `1LL << 32`；两个 int 相乘也要先转成 long long。

### 问题核心

1. 第 t 步移动的盘子编号是 `ν₂(t)+1`，其中 `ν₂(t)` 是 t 的二进制末尾零的个数。也可以看成从 `t-1` 加到 t 时，最低的“由 0 变成 1”的位决定了移动哪个盘子。这里的 t 是总操作次数，与输入的“第 x 次移动 k 号盘”不同。
2. k 号盘的第 x 次移动发生在 `t = (2x-1) × 2^(k-1)`。在第 t 步结束时，已移动过的盘子恰好为 `1…M`，其中 `M = ⌊log₂t⌋+1 = k+⌈log₂x⌉`。因为 j 号盘第一次出现于 `2^(j-1)`，所以已移动编号构成连续前缀。
3. 因此不需要构造 t，只要求最小的非负整数 d 使 `2^d ≥ x`，就有 `M=k+d`；未移动编号之积为 `(M+1)…n = n! / M!`。这样既避开大步数溢出，也把序列问题化成阶乘与逆元查询。

### 解法整理

1. 预处理 `fact=n! mod P` 和所有 `invFact[i]=(i!)⁻¹ mod P`。本地代码使用 `P=998244353`；此做法要求 `n<P`，确保阶乘非零且可逆。先快速幂求 `invFact[n]`，再按 `invFact[i-1]=invFact[i]×i mod P` 倒推。
2. 每次读入合法的 `k, x`，用整数比较寻找 `d=⌈log₂x⌉`，避免浮点对数在 2 的幂附近产生误差；`x=1` 时 d=0。枚举时只需检查到 `k+d=n`，一旦达到 n，所有盘子都已出现。
3. 若 `M=k+d<n`，输出 `fact×invFact[M] mod P`；若 M 达到 n，输出 1，即空乘积。有效询问应满足 `1≤k≤n`、`1≤x≤2^(n-k)`，不额外构造这个上界。
4. 例如 `n=5, k=1, x=3`：d=2、M=3，尚未移动的是 4、5 号盘，答案为 20。

## 错误与卡点

1. 遇到周期序列，先判断答案是否只依赖某个阈值，不必还原整个过程。
2. 模逆元表示模意义下的除法，要求除数与模数互质；C++ 的 `^` 是异或，乘方用快速幂实现。
3. 测试 `x=1`、`x=2^d`、`x=2^d+1` 及所有盘子已移动的边界。

## 复杂度

- 时间：预处理 O(n+log P)，q 次查询 O(q log X)，其中 X 为最大询问次数；按本地 64 位实现，每次最多检查约 61 个幂。
- 空间：O(n)，存储逆阶乘。

## 关键代码

```C++
    //求n!的逆元
    for(int i=2;i<=n;i++)f=(i64)(f*i)%mod;
    g[n]=Pow(f,mod-2);
    for(int i=n;i>=1;i--)g[i-1]=(i64)g[i]*i%mod;
```

# school_2026_round3_A. 随机游走的位移平方期望

- 链接:待补充(校内赛题面)
- 难度:待补充
- 标签:`数学` `概率论` `期望` `随机游走`
- 状态:待补充
- 用时:待补充
- 日期:2026-11-04
- 代码:[本地代码](../problems/school/2026_round3/A.cpp)

## 题意

一个点从原点出发，每步独立地均匀随机选取方向，移动 1 单位长度，求 n 步后到原点距离平方的期望。

## 思路

### 思考路径

1. 我先画每次运动后可能到达的圆，想从图形上判断最终距离，但没有把“位移平方”列成可求期望的式子。
2. 卡点在于不熟悉期望计算：不同路径的终点很难枚举，而直接求距离的期望也不容易。应利用平方展开后的交叉项，以及随机方向的对称性。

### 问题核心

1. 按题目随机游走的含义，每一步方向独立、在 `[0,2π)` 上均匀选取。设前 i 步的位移向量为 `Sᵢ`，下一步单位向量为 U，则 `|Sᵢ+U|² = |Sᵢ|²+1+2Sᵢ·U`。
2. 已知此前所有运动后，Sᵢ 固定，而 U 的平均向量为零，所以交叉项的条件期望为零：`E[Sᵢ·U | Sᵢ]=0`。这比直接写期望乘积更清楚地说明了为什么可以消掉它。
3. 因而 `E[|Sᵢ₊₁|²]=E[|Sᵢ|²]+1`，从初值 0 递推得到答案 n。求的是距离平方的期望，不能把它替换成距离期望的平方。

### 解法整理

1. 把每一步单位位移写成向量，先展开“上一步位移加本次位移”的模长平方，而不是枚举终点。
2. 通过方向均匀且独立，消去点积项的期望，得到每走一步，位移平方的期望恰好增加 1。
3. 从原点开始，初始平方距离为 0，n 步后的结果就是 n；每组数据直接输出 n，无需模拟或浮点运算。

## 错误与卡点

1. 原式中的负号取决于 θ 的定义。若 θ 是当前位移与下一步位移的夹角，展开式应取加号；期望仍因余弦均值为零而消失。
2. `E(XY)=E(X)E(Y)` 需要适用条件，不能仅凭期望线性性使用；这里可以用下一步方向独立，或直接用条件期望说明。

## 复杂度

- 时间：每组 O(1)。
- 空间：O(1)。

# codeforces_1129_Div2_D1. Number Operating (Easy Version)

- 链接:[CF 2277D1 — Number Operating (Easy Version)](https://codeforces.com/contest/2277/problem/D1)
- 难度:待补充
- 标签:`贪心` `递归` `数学` `位运算`
- 状态:待补充
- 用时:待补充
- 日期:2026-11-04
- 代码:[本地代码](../problems/codeforces/1129_Div2/D1.cpp)

## 题意

- 有一个初值为零的x,在一次操作中,你可以对它做一种修改:(修改1)x+2^k,k表示此操作前连续的修改1次数；(修改2)x-1。定义f(n)为x变成n的最小操作数。求Σf(n),n∈[l,r]

## 思路

### 思考路径

1. 我把连续 k 次加法看成一个块：它增加 `2^k-1`；如果后面再减 1，净增量变成 `2^k-2`，代价为 `k+1`。于是尝试把目标表示成若干块之和，并贪心让 k 尽量大。
2. 随后想到减 1 可以连续进行，所以答案不一定来自“恰好凑出 n”：先超过 n，再连续减回去也可能更优。这是只做分块贪心时遗漏的路径。
3. 原笔记已经记录了递推式，但没有交代两项分别代表什么，以及递归为什么终止；还需要把小值特判和区间求和补上。

### 问题核心

1. 连续加法块之后的减 1 既调整数值，也重置连续加法计数，因此可以把它们合成“净增 `2^k-2`、花费 `k+1`”的操作单元。
2. 设 `2^k≤n<2^(k+1)`。按官方题解的分块结论，只需比较两条路径：做 k 次加法再减一次，递归补齐差值；或做 k+1 次加法超过目标，再连续减到 n。小于 k 的首块不会更优。
3. 第一条花费 `k+1+f(n-2^k+2)`；第二条花费 `k+1+(2^(k+1)-1-n)`。二者取最小，避免“只向上凑数”的片面贪心。

### 解法整理

1. 设置边界：`f(0)=0, f(1)=1, f(2)=3, f(3)=2`。其中 2 可以通过 `+1,+2,-1` 达到，3 通过 `+1,+2` 达到。
2. 对 `n≥4`，用整数位运算求 `k=⌊log₂n⌋`，计算 `f(n)=min(k+1+f(n-2^k+2), k+2^(k+1)-n)`。递归参数严格变小，且经过至多常数次递归后最高位下降，递归深度为 O(log n)。
3. Easy Version 可以直接遍历 `[l,r]`，逐个计算 f 并累加，最后对 `998244353` 取模；累计和也可以边加边取模。
4. 最小值比较使用真实操作次数，不能在 `min` 的候选代价中先取模。原本地代码的第二项在比较前用了 `%mod`，整理时应采用上述未取模的递推式；这里只完善笔记，不改动源代码。
5. 例如 n=4：两条路径分别为 `3+f(2)=6` 和 `2+8-4=6`，故 f(4)=6。

## 错误与卡点

1. 区分“状态大小很大”和“区间长度很大”：D1 的数值上界很大，但可以遍历区间内的整数；单点递归足够快。
2. 小值边界必须先处理，否则 n=2、3 时第一分支不会缩小参数。
3. 位移和候选代价使用 64 位整数；原 `Log` 辅助函数只应在正数上调用。

## 复杂度

- 时间：O((r-l+1) log V)，V 为区间内最大数值，按固定字长整数求最高位。
- 空间：O(log V)，来自递归栈。

## 关键代码

```cpp
int Log(i64 x)
{
    int res=0;
    for(int i=5;i>=0;i--)
        if(x>=(1LL<<(1<<i)))
        {
            x>>=(1<<i);
            res+=(1<<i);
        }
    return res;
}
```

# school_2026_round4_C. 整数因子与乘积最大值

- 链接:待补充(校内赛题面)
- 难度:待补充
- 标签:`数学` `因数枚举` `整数约束`
- 状态:待补充
- 用时:待补充
- 日期:2026-11-04
- 代码:[本地代码](../problems/school/2026_round4/C.cpp)

## 题意

- 已知非负整数a,b满足a+b+ab=x,x已知,求ab最大值

## 思路

### 思考路径

1. 我尝试用 `a+b≥2√(ab)` 把等式转成只含 ab 的不等式，再通过浮点计算和取整求最大值。
2. 失败原因是这个过程给出的只是实数范围内的上界。a、b 必须是整数，取得上界的实数解不一定合法，直接取整也无法保证原等式成立。

### 问题核心

1. 给等式两边加 1：`(a+1)(b+1)=x+1`。令 `u=a+1, v=b+1`，非负整数 a、b 就对应正整数因子对 `uv=x+1`。
2. `ab=(u-1)(v-1)=x+2-(u+v)`，所以最大化 ab 等价于在因子对中最小化 u+v。
3. 设 `u≤v`，则 `u≤√(x+1)`。在这个范围内，`u+(x+1)/u` 随 u 增大而减小，因此应找不超过平方根的最大约数；它与配对因子最接近。

### 解法整理

1. 令 `N=x+1`，取 `s=⌊√N⌋`。为了避免浮点误差，可在 sqrt 后用整数除法校正，使 `s≤N/s` 且 `s+1>N/(s+1)`。
2. 从 s 向下枚举 u，找到第一个满足 `N%u==0` 的数；令 `v=N/u`，答案为 `x+2-u-v`。找到后立即结束，不必枚举全部因子对。
3. 若 u≥2 时没有因子，使用 `u=1,v=N`，得到 ab=0，对应 a=0。x=0 也得到 0；实现时还要保证 `x+1` 不超出整数类型范围。
4. 例如 x=11，则 N=12，最接近的因子对为 3、4，对应 a=2、b=3，最大乘积为 6。

## 错误与卡点

1. 不等式的等号条件只能给出候选方向，整数题还需要验证整除性。
2. 式子出现 `a+b+ab` 时，可以优先尝试补 1 后因式分解。
3. 校正平方根时使用除法比较，避免 `s*s` 溢出。

## 复杂度

- 时间：每组最坏 O(√(x+1))。
- 空间：O(1)。

# school_2026_round4_D. 两次询问确定坐标

- 链接:待补充(校内赛题面)
- 难度:待补充
- 标签:`交互题` `数学` `曼哈顿距离`
- 状态:待补充
- 用时:待补充
- 日期:2026-11-04
- 代码:[本地代码](../problems/school/2026_round4/D.cpp)

## 题意

- 给出范围[0~n],通过两次询问查找其中的a,b值,每次询问输入x,y,返回|a-x|+|b-y|

## 思路

### 思考路径

1. 原记录主要写了“交互题”和“不熟悉代码要求”，没有保存更多算法尝试，因此这里只保留这个实际卡点，不额外补写当时不存在的思考过程。
2. 数学方案是询问 `(0,0)` 和 `(0,n)`，但最初没有说明这两个点为什么足够。实现上需要输出询问并刷新缓冲区，再读取返回值，否则双方可能一直等待。

### 问题核心

1. 已知 `0≤a,b≤n`，把询问点放在边界可以去掉绝对值。询问 `(0,0)` 得到 `d₀=a+b`，询问 `(0,n)` 得到 `d₁=a+n-b`。
2. 两个式子相加、相减即可解出 `a=(d₀+d₁-n)/2`、`b=(d₀-d₁+n)/2`。因此关键是选取能把距离函数变为两个独立线性方程的边界点。
3. 刷新缓冲区是交互协议的实现条件；与“为什么两次就能求出坐标”的数学核心分别理解。

### 解法整理

1. 读取 n，输出 `? 0 0` 并换行、刷新，读取 d₀；再输出 `? 0 n` 并换行、刷新，读取 d₁。也可以采用本地代码中的相反询问顺序，但必须对应好返回变量。
2. 按上述公式计算 a、b。合法返回值会保证分子为偶数，结果落在 `[0,n]` 内；中间和使用 64 位整数。
3. 输出 `! a b` 并换行、刷新，按原题协议结束该组交互。若协议规定错误返回值或结束标记，也应按其要求及时退出。
4. 例如 n=10、隐藏点为 (3,7)，有 d₀=10、d₁=6，代回得到 a=3、b=7。

## 错误与卡点

1. `printf` 搭配 `fflush(stdout)`，`cout` 搭配 `cout.flush()` 或 `endl`；二者分别刷新对应的流，关闭同步后不能当成无条件等效的替换。
2. 换行本身不保证输出已发送；每次询问后都要刷新，再等待回复。

## 复杂度

- 时间：O(1)，共 2 次询问。
- 空间：O(1)。

## 关键代码

```cpp
    fflush(stdout);
    cout.flush(); //等效
```

# school_2026_round4_E. 街道店铺访问

- 链接:待补充(校内赛题面)
- 难度:待补充
- 标签:`动态规划` `坐标离散化`
- 状态:待补充
- 用时:待补充
- 日期:2026-11-04
- 代码:[本地代码](../problems/school/2026_round4/E.cpp)

## 题意

- 一条街道两侧有店铺,部分位置有过街通道,从位置0出发,不允许回头和多次通过一条过街通道,求能经过的最多店铺数量

## 思路

### 思考路径

1. 我注意到坐标范围大而店铺、通道数量少，先想到离散化；状态则考虑 `f[i][0/1]`，分别表示走到第 i 个位置、位于道路两侧的最多访问数。这两个方向是对的。
2. 实现卡在离散化不熟悉，以及转移方程没有理清同一坐标处的店铺计数。过街时会先访问原侧店铺，再访问目标侧店铺；但不能在同一个通道来回更新，把同一位置重复计数。
3. 原记录只有“离散化+DP”，缺少状态语义、初始状态和有无通道的区别；下面根据本地实现补全。

### 问题核心

1. 不允许回头意味着按坐标从小到大处理即可。两处事件之间没有新店铺或通道，实际间距不影响答案，所以只需保留所有店铺和通道坐标的相对顺序。
2. 处理完某个坐标后，对将来有影响的信息只有“停在哪侧”和“最多访问了多少店铺”，不必记录此前路线。两侧各保留一个最优值就足够。
3. 有通道时，要么一直在当前侧，要么从另一侧走到该坐标并过街一次；跨越通道可以访问同坐标的两侧店铺。两种目标状态都必须从上一坐标的状态计算，不能使用刚刚更新的同层状态。

### 解法整理

1. 将左侧店铺、右侧店铺、通道的全部坐标放入同一个数组，排序去重。对每个离散位置 i 记录 `Lᵢ,Rᵢ,Cᵢ`：两侧店铺数量以及是否有通道。本地代码把 L、R 标成 0/1，对应每侧每坐标至多一家店；若原题允许重合店铺，应改为累加数量。
2. 定义 `Fᵢ[s]` 为处理完第 i 个坐标后，停在 s 侧的最多访问数。以下与本地代码一致，按坐标从 0 向前、起点两侧可任选的条件，令 `F₀[0]=F₀[1]=0`。若题面固定起始侧，则另一侧必须设为负无穷；当前笔记未记录这一条件，仍需核对原题。
3. 若当前位置没有通道，只能沿原侧走：`Fᵢ[0]=Fᵢ₋₁[0]+Lᵢ`，`Fᵢ[1]=Fᵢ₋₁[1]+Rᵢ`。
4. 若有通道，分别比较不过街和过街：`Fᵢ[0]=max(Fᵢ₋₁[0], Fᵢ₋₁[1]+Rᵢ)+Lᵢ`；`Fᵢ[1]=max(Fᵢ₋₁[1], Fᵢ₋₁[0]+Lᵢ)+Rᵢ`。例如从右侧过到左侧，新增右侧店铺 Rᵢ 和左侧店铺 Lᵢ 各一次。
5. 按序处理全部离散位置，输出 `max(F_last[0],F_last[1])`。DP 可只存前后两层，但坐标及事件数组仍需保留。

## 错误与卡点

1. 离散化必须同时收集所有会影响转移的事件：只压缩店铺而漏掉通道，会丢失换边机会。
2. 不要在一个坐标处先更新左侧、再用新左侧更新右侧，否则相当于允许重复过街。
3. 本题说明基于原笔记和本地代码重建，公开题面缺失；起点所在侧、坐标方向和重合店铺规则仍需对照原题确认。

## 复杂度

- 时间：O(S log S)，其中 S 为两侧店铺数与通道数之和；DP 本身 O(S)。
- 空间：O(S)，用于离散坐标与事件。

- 日期:2026-11-04
- 代码:[本地代码](../problems/school/2026_round4/F.cpp)

## 题意

- 给出一个整数序列,可以对其中任意数s做以下任意次操作:将s变为s*2；将s变为s*4+1；将s变为s*4+3,求操作后最少有多少数不同

## 思路

### 思考路径

1. 我先将三种操作理解成在二进制末尾追加 `0`、`01`、`11`，并尝试把“两个数最终相同”转成“一个是另一个的前缀”。随后想到排序去重，对大数不断右移，再用 lower_bound 查找输入中是否有匹配值。
2. 卡点之一是直接两两匹配会达到 O(n²)；另一个是误以为三种片段可以拼出任意后缀。普通前缀关系只是必要条件，后缀还必须能按合法片段分解。
3. 例如二进制 `11`（3）虽是 `111`（7）的前缀，但补上的单个 `1` 不是合法操作片段；7 的唯一正数父节点是 1，并不会经过 3，所以两者无法变成同一个数。

### 问题核心

1. 正数的最后一次操作可以由末尾唯一确定：偶数只能来自 `s×2`，父节点为 `v/2`；奇数若模 4 余 1，则来自 `s×4+1`；若余 3，则来自 `s×4+3`，两种情况下父节点都为 `⌊v/4⌋`。父节点必须仍为正数，否则逆向路径终止。
2. 因此正整数形成一片父节点唯一的树结构。一个数能变为另一个数，当且仅当它在后者的祖先链上。两个不同分支的后代不可能相交，否则交点会出现两条不同的祖先路径。
3. 输入中没有任何其他输入后代的节点必须各自贡献一个不同终值，这是答案下界；其余输入节点可向下变到某个这样的后代，所以这个下界可达到。答案就是输入集合中“不再有其他输入后代”的节点数。

### 解法整理

1. 排序并去重得到数组 a。相同的输入值可以保持一致，只需要处理一次；这里只采用本地代码所对应的正整数条件。
2. 从大到小扫描。若当前值已经标记，说明它能被某个更大的输入后代合并，直接跳过；否则它需要单独贡献一个终值，答案加 1。
3. 从当前值沿唯一父链向上走：偶数右移 1 位，奇数右移 2 位。父值为 0 时结束；对正父值用 lower_bound 查找是否在 a 中，在则标记。小于数组最小值后也可直接结束。
4. 如果遇到一个已经标记的输入祖先，可以停止：此前处理该节点或其后代时，它上方所有相关输入祖先也已经被处理。这里标记的是可被合并的“小祖先”，而不是删除当前大数。
5. 最终计数即最少不同数的数量。例 `[1,2,5]` 中，1 可以变成 2 或 5，但 2、5 分属不同分支，答案为 2；不能因为它们都有祖先 1 就全部合并。

## 错误与卡点

1. 判断可达性时，合法操作片段比普通二进制前缀关系更强；应从末尾反推最后一次操作。
2. 原副本中“奇数不能直接右移两位”的待核对提示过于笼统：在正整数域内，模 4 余 1、3 分别对应两种合法操作，因此两位右移正确，边界是父节点不能变成 0。
3. 若题面允许输入 0，需要单独处理 0 的可达关系并保证循环终止；本地程序在最小值为 0 时可能无法退出。本笔记不把这份正整数算法无条件扩展到含 0 的输入。

## 复杂度

- 时间：O(n log n + U log A log U)，U 为去重后的数量，A 为最大输入值；每次父链查询用二分。不能直接忽略 log A 而写成一般意义上的 O(n log n)。
- 空间：O(n)，存储数组与标记。

# school_2026_round3_F. 楼梯方案计数

- 标签:`计数动态规划` `后缀和优化` `滚动数组` `预处理`
- 状态:待补充
- 用时:待补充
- 日期:待补充
- 代码:[本地代码](../problems/school/2026_round3/F.cpp)

## 题意

- 一个楼梯有n个部分,每个部分都有一个正整数长度,长度依次非递增,第i+1个部分需要接在第i部分的上端或下端。现需要一个高度为m的楼梯,问有多少种不同的方案。

## 思路

### 思考路径

1. 我先考虑计数 DP：用 `f[i][j][k]` 记录由 i 个部分组成、总高度为 j、最后一段长度为 k 的方案数；上一段长度必须至少为 k，所以转移要对上一段长度求和。
2. 为了避免每次转移再枚举长度，我想到对长度维做累计求和。原笔记写成“前缀和”，但实际求的是 `[k,j]`，应叫后缀和；同时 g 的定义误用了 `f[i-1]`，与后面的 `g[i-1]` 转移多差了一层。
3. 我接着发现只有前一层参与转移，可以使用滚动数组；f 也只是中间值，可以直接用 g 的后缀递推维护。
4. 最后考虑到测试组数很大、状态转移不依赖某一组特定的 n，决定预处理所有 `ans[n][m]`，每组只查表。这个思考顺序是“建状态 → 优化区间求和 → 压缩空间 → 多组数据共用预处理”。

### 问题核心

1. 非递增限制使“上一段长度 l≥当前长度 k”成为连续后缀区间；这是能用后缀和优化枚举的关键。
2. 按原笔记及本地实现的连接模型，新增一段长度 k 有两类贡献：总高度仍为 j，或从 j-k 增加到 j。因此 `f[i][j][k]=Σ(l=k…j)f[i-1][j][l]+Σ(l=k…j-k)f[i-1][j-k][l]`。原题面未存档，此处沿用记录中的几何模型，不额外推定其他连接规则。
3. 统一定义 `g[i][j][k]=Σ(l=k…j)f[i][j][l]`，则 `f[i][j][k]=g[i-1][j][k]+g[i-1][j-k][k]`。第二项在 `j-k<k` 时为 0，而 `g[i][j][k]=g[i][j][k+1]+f[i][j][k]` 可从 k 大到小计算。
4. 最终答案要统计所有末段长度，恰好为 `g[n][m][1]`。转移只依赖上一层 i，可以滚动存 g；所有询问共享同一套状态，适合一次预处理。

### 解法整理

1. 设最大部分数为 N、最大高度为 M；本地代码均预处理到 600。所有计数对 `P=998244353` 取模，先将数组清零。
2. 初始化 i=1：只有一段时长度必须为 j，因此 `f[1][j][j]=1`，其余为 0；于是对所有 `1≤k≤j` 有 `g[1][j][k]=1`，并记录 `ans[1][j]=1`。
3. 对 i 从 2 到 N 枚举；对每个 j，将当前滚动层的 `g[cur][j][j+1]=0`，再令 k 从 j 递减到 1。取 `x=g[prev][j][k]`；若 `j-k≥k`，再加 `g[prev][j-k][k]`。
4. 令 `g[cur][j][k]=(g[cur][j][k+1]+x) mod P`，从而无需额外存 f。每算完一个 j，保存 `ans[i][j]=g[cur][j][1]`；当前层计算完后再交换滚动层。
5. 每组 `(n,m)` 直接输出 `ans[n][m]`。这里滚动的是 g 的 i 维；ans 仍保存全部 n、m 的答案，不能一起滚动丢掉。
6. 快速检查：n=1 时任意正高度恰有 1 种；按上述递推，n=2 时有 `1+⌊m/2⌋` 种，分别来自保持高度和增加高度两类。

## 错误与卡点

1. g 的定义必须与其层数一致，不能一边定义在 `f[i-1]` 上，一边又访问 `g[i-1]`。
2. k 维使用后缀递推，所以必须倒序；每行的 `j+1` 哨兵要重置为 0，防止滚动层残留。
3. 当两个加数都在 `[0,P)` 内时，和小于 2P，可用一次条件减法代替 `%P`；不要对三个未经归约的加数直接套用该结论。
4. 多组询问时，除了降低单次转移成本，还要检查能否把与当前询问无关的状态统一预处理。

## 复杂度

- 时间：预处理 O(NM²)，T 组查询共 O(T)。
- 空间：O(M²+NM)，分别用于滚动 g 和答案表 ans。
